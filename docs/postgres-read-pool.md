# PG 主库读取连接池

正式服务把独立读取从写连接上分开：写入仍按记录/操作号分片，所有分片共享同一个租户级读取池。读取取当前可用的连接，池满时按等待队列排队。读写都连接配置中的同一个 PG 主库，没有新增从库地址或改变一致性契约。

## 配置与连接预算

`storage.postgresReadConnections` 默认 `2`，范围 `0..64`；`0` 显式恢复原先读写共用连接的行为，可用于诊断/回退。`storage.shards` 继续控制写请求连接数量。本地配置明确使用 4 条写连接和 2 条读连接。修改数量需要重启服务。

每租户每实例的常驻 PG 连接数为：

`写分片数 + 读池大小 + 2 条维护连接`

两条维护连接分别用于共享的 Outbox/缓存修复队列，以及普通回执清理。4 写 + 2 读时共 8 条；同一实例两个租户共 16 条；两个实例各两个这样的租户共 32 条，**不能部署到本轮 max_connections=30 的测试 PG**。还要给管理、迁移工具、监控以及 PG 保留连接留空间。应按全部实例求和配置，不得用无限扩容连接应对排队。启动日志按租户输出连接数量；启动失败不会退回原共用连接模式。

读池启动时一次性建立固定数量连接，所有写分片共享这组连接，不按分片再乘一遍。独立使用 `PostgresSnapshotStore` / `TieredSnapshotStore` 的管理和测试代码保持原有构造语义；由正式 `StorageBackend` 统一创建并附加读池。

## 覆盖及保留语义

读池覆盖代码中的六个独立 PG 读取入口：单条快照、批量快照、单记录事务回执、多记录/通用提交回执、交易状态、交易回执。缓存未命中和后台刷新回源经由前两个入口读取 PG，不是额外入口。缓存策略仍由原 Tiered 存储实现处理；批量权威读取保持单条 SQL 的一致快照。写事务内部的查重、条件检查和查询仍留在原事务及写连接，不能拆出去。

有一处写路径会用到读池：普通保存或排队保存返回“重复请求”时，写事务已提交并释放写连接，随后为刷新缓存而回读该记录的快照，这次回读走读池。已提交版本在任何新连接上都可见，结果不受影响；但读池满时这次回读会返回连接等待错误，调用方按原请求号重试即可。写事务本身不占读池名额。

默认权威读取仍返回主库已提交状态；PG 失败不退回旧缓存。读取与尚未完成的写入并发时，可以看到此前已提交版本；业务若要求“写完再读”，必须先等待写入成功。客户端同一连接/同一记录的已有排序机制并未删除，因此本功能不保证绕过客户端侧的所有等待。

读池取得连接使用已有 `postgresConnectionWaitTimeoutMs`（默认 2,000 ms），满池超时返回现有连接等待错误；该预算不包含 SQL 执行时间。重连复用已有超时和 `postgresReconnectCooldownMs`（默认 500 ms）。取消等待不会占住名额；持有连接的任务取消、出错或完成后归还名额。取消 Rust 查询 future 不等于立即取消 PG 端 SQL，连接仍保留原协议的顺序处理语义，不能将“名额已归还”解释为 PG 查询必已结束。

`postgres_read_pool_wait` 为新增有限指标标签，记录池容量等待；仍计入原来的 `postgres_connection_wait`，执行和重连继续计入 `postgres_operation`。这两个等待指标有包含关系，不能求和。回执清理和写事务不使用读池；写路径中只有上述重复写的回读会取读池名额。

## 验证入口

历史问题与对照见[相同连接数与受控阻塞](acceptance-equal-connections-20260922.md)。新实现使用 `acceptance_host` 的 `-ReadConnection pooled`：正式后端 4 写 + 2 读，不经过历史 `DedicatedReadProbe` 适配器；`shared` 和 `dedicated` 保持原来的诊断含义。

真实集成需要隔离 PG/Redis、新库和明确迁移开关。用例包括：

- `read_write_contention::production_read_pool_bypasses_blocked_writes_over_tcp`：保持写入阻塞，检查同分片读取、批量读取、单/批缓存回源和回执/交易读取；客户端共用 8 条和读写各 4 条交错重复。
- `postgres_read_pool::tests::real_read_pool_paths_capacity_cancellation_and_reconnect`：占住写连接检查六个独立 PG 读取入口；占满两条读连接验证等待超时、取消等待、取消占用任务不会遗失池容量；终止本测试的两条 PG 读连接后，通过普通读取自动重连并核对结果。
- 原有权威读取真实网络测试检查旧缓存/负缓存不能冒充权威值、批量快照一致性，以及 PG 被锁时不能降级缓存。

这是连接隔离改动，不消除磁盘瓶颈或数据库锁冲突；正式综合负载、故障矩阵和两小时验收需分别留证，不能由普通读写短测替代。

本轮真实实施结果见[验证报告](acceptance-read-pool-20260922.md)：功能/恢复通过，但三轮新读池短测漏发 2 / 9 / 0，尚不能进入两小时验收。
