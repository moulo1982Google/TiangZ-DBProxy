# PostgreSQL 连接排队诊断（0.7）

本次补齐观测，未改变默认 2000ms 连接锁等待预算、SQL 执行行为、事务提交/幂等契约、分片数或后台 worker 数。R10/R11 的普通窗口超时根因仍待新版本证据确认；不能把日志改造称为排队性能修复。

## 服务日志

每个实际连接及其克隆/维护队列共用同一个诊断状态。请求分片启动时登记 `request` 与分片下标；独立轮询连接登记 `maintenance`。`pg_stat_activity.application_name` 使用 `tzdb:<服务进程 PID>:<角色>:<分片>`，日志中的 `backend_pid` 与 PostgreSQL 实际 PID 对应。登记通过额外的只读 PID 查询及会话 application_name 设置完成；首次登记和断线后的登记有独立 2000ms 上限，不为已发送的业务 SQL 增加超时。重连后重新登记 PID 并递增代次，未登记或正在断线的 PID 明确为 null。

- `queue_timeout`：等待请求的本进程序号、操作类型、操作号 SHA-256 前 8 字节、批量大小、已等待时间；同一连接的当前持有者及持有年龄、等待者数量和最老被追踪等待年龄；最近 8 次释放的完整持有时长。
- `slow_hold_released`：连接锁占用达到 500ms 后释放时记录完整范围时长，包含重连、查询、事务和 COMMIT 回包等待。范围释放可能来自正常返回、错误或取消；**不表示事务提交成功**。队列告警与释放告警独立限流，各连接每类最多每秒一条。
- `postgres diagnostic connection identified`：启动和重连后的 PID/角色/分片/代次映射，info 级别。

操作标记区分 `backlog_save_batch`、普通 `save_batch`、`cache_repair_load`、直接读取、事务、交易和各维护队列方法。批量写的关联哈希对应批次第一条请求号；事务/交易的关联哈希对应原操作号。负载工具使用同一哈希算法；重试保持原号，不记录业务载荷、完整 SQL、凭据或原始操作号。分片/操作号不会加入 Prometheus 动态标签。

诊断保留最多 128 个等待者元数据及 8 条完成历史。额外等待者仍按原策略等待，并以 `untracked_waiters` 明确报告；最老等待时间只覆盖已追踪者。等待取消/期限耗尽会移除元数据，持有者在实际解锁前移除，避免迟到清理擦除新持有者。记录不改变业务准入或提交结果。

`dbproxy_storage_stage_timeouts_total{stage="postgres_connection_wait"}` 现在在连接锁期限确实耗尽时计数，包含共享请求连接的缓存修复 ACK；普通取消、重连冷却、SQL 错误不冒充锁超时。历史零值存在漏计，不能用于证明旧测试没有 PG 排队超时。

## 故障负载错误记录

`dbproxy_fault_soak` 保留最近 64 条错误，每条错误文本最多 512 个字符，带 UTC Unix 毫秒时间、序号、阶段、可重试分类及可选操作号哈希。首 16 条仍即时输出，之后最多每 10 秒输出一条即时样本；每个进度周期有新错误时另输出 `SOAK_RECENT_ERRORS`，最终报告包含 `errorDiagnostics`。首轮故障不会耗尽后续样本额度。突然强杀无法产生最终报告，但此前的周期记录会保留。

永久契约错误计数、正常窗口失败规则、故障恢复门槛与负载速度均保持原样；采样和样本淘汰不减少总错误或不变量计数。

## 验证与版本边界

针对性回归覆盖：锁超时前未发送 SQL、超时只计一次、取消不计超时、不丢失当前持有者、完成历史与等待记录固定容量、早期故障后仍保留晚期错误、实际 PostgreSQL PID 映射、SQL 持有者和重连代次。真实数据库用例只在独立可迁移测试库运行。

云端当前旧版本 240 分钟保持冻结。完成完整负载、额外 300 秒无负载观察、实际正常退出及独立原始证据复核后，按原资源身份正常停止，再切换新版本。新 server 与新 fault-soak ELF 必须分别绑定源提交和 SHA-256。新版 480/960/1440 分钟各完整重新计时；旧版通过的阶段仍属于旧版，不能冒充新版的长稳资格。
