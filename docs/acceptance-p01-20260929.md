## 测量约定

- 正式 release DP，同一进程两个租户，每租户独立新 PG 库与缓存逻辑 DB，同名业务键使用不同载荷以核对隔离。
- 每库先写入 512 条 1 KiB 快照，选择每个 HASH 分区两条，64 条覆盖全部 32 个分区。批量大小 1/30/64；先核对首位、中位、末位缺失时的结果位置。
- 三条路径：默认权威读 `load_multi`；重复缓存读 `load_cached_multi`；每次读取前仅删除本轮精确缓存数据/新鲜标记/负缓存的冷缓存读。保留 revision fence，不清 Redis DB，不碰其他业务键。
- “冷”指 Redis 快照缓存，不是清 PG buffer 或宿主页缓存；“热”沿用产品默认 TTL，周期性刷新仍可能发生，不伪装成永不失效的纯内存命中。
- 每租户 10 RPC/s，每租户最多一个请求在途，两个租户并发；每场景预热 120 秒、采样 300 秒，共 9 场景 × 3 轮，交替正反顺序，约 189 分钟。
- 每个 RPC 保存原始耗时、准备耗时、调度延迟。冷缓存准备不混入 RPC 计时，另行报告；固定速率不足的情况从实际计数/秒数可见。保留全 SQL EXPLAIN ANALYZE/BUFFERS、阶段前后 PG/服务指标与容器 CPU/内存/IO。
- 最后对 64 条跨分区记录进行 100 次原子更新，200 次 TCP 权威批量读取必须各自只看到一个已提交版本，最终 revision=101，另一个租户仍为 1。缓存批量接口不作这种跨记录原子版本保证。

工作容器 4 CPU/16 GiB、固定 CPU 集合。运行前要求宿主可用内存至少 12 GiB；运行中连续 30 秒低于 8 GiB 则停止本轮工作容器。单次读取超过 2 秒直接失败，不继续加压。三轮期间不并行运行编译或其他验收负载。
