# F15 补测：监控采集失败时业务独立提交

RunId `monitor_20260929a`，新数据库 `_f15mon_a/b`，真实双租户 release 服务。Linux 实际运行一项测试通过，耗时 15.34 秒。未改生产代码或协议。

## 注入和核对

监控采集经过测试内部转发器，业务连接始终直连 DBProxy。正常阶段转发 HTTP；故障阶段只收请求、不返回内容，采集方以 300ms 截止时间断开；恢复阶段重新转发。每阶段各采集十次，故障阶段必须十次全超时，正常和恢复阶段必须十次全为 HTTP 200 且含实际指标。

故障阶段另外向租户 A 的真实监控端口建立 16 条连接，发送不完整 HTTP 请求，不再补齐。要求这些连接由生产监控服务的读超时关闭。连接数量固定，不做无界连接耗尽。

与采集并发的业务任务每阶段为两个租户各写 40 个相同键、不同载荷的记录，并逐笔读取验证。每次读写的测试截止时间为 2 秒；成功写入必须 Applied、revision=1。最后分别直连两个 PG 数据库，逐笔检查全部键、载荷和版本，确认数据实际提交且未串库，不仅检查 SDK 缓存或总行数。

## 结果

| 阶段 | A/B 写入 | SDK 读核对 | 采集成功/超时 | 最大写耗时 |
| --- | --- | ---: | --- | ---: |
| 正常 | 40 / 40 | 80 | 10 / 0 | 7.864ms |
| 采集链路中断 | 40 / 40 | 80 | 0 / 10 | 5.218ms |
| 恢复 | 40 / 40 | 80 | 10 / 0 | 4.787ms |

240 笔业务记录直接 PG 核对全部一致，16 条不完整监控连接全部关闭。未重启服务，两个租户最终指标端点均正常。

范围：证明本轮受限流量下监控**采集路径**短时不可用及不完整请求不会阻止正确提交。不等于杀死进程内 exporter 监听任务、不等于独立监控服务进程崩溃测试，也不证明无限慢连接的资源上界。F15 原计划中的监控服务自身不可用变体仍保留为缺口，不能把路径故障扩大为全部故障。
