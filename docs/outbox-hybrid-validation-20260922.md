# Outbox 领取查询改写验证（2026-09-22）

继[候选排查](outbox-backlog-validation-20260922.md)后，本轮采用“小批候选优先，必要时按组查找”的组合。正式 SQL 已更新，无新增表、索引或迁移；数据库版本仍为 014。普通回执 7 天保留尚未实现。

## 行为

1. 按原 enqueue_order 找到最靠前的最多 32 条到期、未发布、非死信且没有有效租约的候选。此处不锁行。
2. 用现有分组索引检查前序消息，按原顺序尝试锁定并领取一条。对真正锁定的业务行再次检查发布、死信、日期和租约状态，防止候选列表生成后并发状态变化导致重复领取。
3. 候选存在但都被前序消息或行锁挡住时，汇总每组最早未发布序号，再按原顺序查找可锁定的一条。只在需要时执行这段查询；publisher 指定时汇总也限制该 publisher。
4. 快速路径与后备路径最多只有一路返回一条消息，沿用原 UPDATE 写租约、计数和返回值。

死信、延后重试和有效租约的队首仍阻塞同组后序消息。组键仍是 publisher、destination、partition_key。SKIP LOCKED 允许其他组推进，不保证多个并发工作者的完成顺序。

**32 只是快速路径的候选数，不是读取行数或页数上限。** 找候选仍可能扫描和排序大量任务；后备路径也可能扫描整个未发布集合。没有维护额外队首表，没有引入索引写入成本，但不能宣称查询成本与积压大小无关。

## 正确性与回归

- 四种队首状态各跟随 40 条同组消息，超过候选大小，验证后备路径不会让同组后序越过队首，独立组仍能推进。
- 锁住最早 40 条独立组消息，8 个工作者同时领取，得到第 41～48 条且不重复；解锁后，剩余消息按原顺序连续领取。
- 既有租约过期、重领、管理员重试、原子提交和路由分组测试继续通过。九种性能分布核对实际返回消息或空结果，并检查快速/空路径不执行全队列分组汇总。
- 本轮真实数据库测试：索引结构 3、存储 22、缓存修复并发 8、网络 2、Outbox 并发与顺序 8、Outbox 九分布 1、通用查询 3、缓存领取分布与顺序 2，共 **49 项通过**。
- Rust 工作区 188 项、TypeScript SDK 21 项、格式、Clippy、Actions 配置检查通过。没有协议变更；SDK 测试按既有命令运行生成和构建。未运行独立 Outbox Redis 发布往返、完整故障矩阵、长时间压力或远程 CI。

CI 索引任务增加 `outbox_hybrid_plans`，Outbox 并发仍使用单独测试库。旧版本 SQL 固定保存在测试夹具；比较和正式运行的新查询直接引用同一个生产 SQL 文件。

## 同轮发现的缓存修复测试问题

完整回归首次在缓存修复 backoff 页数断言失败：旧样本每行使用 clock_timestamp 生成稍有不同的重试时间，统计抽样会影响索引选择，新查询实际读到 734 页，而不是此前样本的约 20 页。Outbox 改写没有修改该查询，这暴露了原页数结论的适用范围。

修正方式：固定重试/租约时刻的可重复分布继续保留页数断言；另外显式加入 `backoff-varied`、`leased-varied`，记录计划并核对领取结果，不对这两种变化时间分布承诺固定读取上限。没有强制执行计划或删除失败证据。**缓存修复在变化日期分布下仍可能读取较多索引页，后续应继续测量，不把本轮通过当作已解决。** 修正后两项缓存领取测试通过。

设置独立测试库 URL 和 `DBPROXY_TEST_ALLOW_SCHEMA_MIGRATION=1`；查询样本与并发测试分别使用不同测试库且串行执行：

```powershell
cargo test -p tiangz-dbproxy-storage --test outbox_hybrid_plans --test query_plans --test repair_claim_plans --locked -- --ignored --nocapture --test-threads=1
cargo test -p tiangz-dbproxy-storage --test outbox_concurrency --locked -- --ignored --nocapture --test-threads=1
```

日志：`target/outbox-hybrid-validation/`。最终并发结果为 `concurrency-final.log`；`all-plans.log` 保留首次缓存断言失败以及成功的 Outbox/通用查询结果；修正后缓存结果为 `repair-plans.log`。基础真实回归、工作区和 SDK 日志分别留存。
