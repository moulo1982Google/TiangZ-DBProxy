## 下一步实施顺序

### 1. 先确认排队和取消边界

入口：`crates/dbproxy-storage/src/lib.rs` 的 `SharedPostgresClient`、`ReconnectingPostgresClient::ensure_connected`、`open_postgres`，以及 `PostgresSnapshotStore` 各读写入口；继续检索 Trade、CommitRecords、持久化修复 ACK 和维护 Worker 的全部调用点。

当前共享客户端是 `Arc<Mutex<ReconnectingPostgresClient>>`，闭合连接在持锁时重连，单次连接预算 2 秒。需要验证故障期间多个等待者是否依次消耗重连预算，以及请求取消后是否仍占用队列/服务端执行资源。不能仅凭直方图断言纯 SQL 慢。

先列出四种状态：等待连接尚未发送、正在重连、SQL/事务已发送、提交已完成但回执未收到。逐一确认现有错误映射、连接可复用性和幂等回执查询路径。

### 2. 最小化实现有界等待

- 优先评估在**未取得连接、尚未发送 SQL** 的边界限制等待时间，返回可重试的存储不可用；数值根据精确测试和新机器基线决定，不预设照搬缓存 200 ms。
- 若精确用例证实重连失败形成串行风暴，再考虑同连接共享失败冷却/单次恢复探测；与现有 PG 回源熔断职责分开，避免再加一套泛化状态机。
- 分别评估请求分片、维护连接、提交后缓存修复 ACK；不要通过修改通用锁封装意外改变所有 Worker。
- 配置如确有必要新增，同步默认值、校验、Schema、模板、兼容说明和启动接线；不提前增加尚无执行语义的开关。
- 沿用固定标签的 `postgres_connection_wait` / `postgres_operation` / `cache_repair_ack` 和 SDK queue/exchange 指标；只有无法区分拒绝原因时才新增有限基数计数。

### 3. 正确性硬约束

- 不给整个写事务简单套一个短 timeout 后声称“写入未发生”；取消 future 不证明 SQL 停止或事务回滚。
- 保留 request/operation ID、revision/CAS、幂等指纹和重复回执。提交结果未知必须沿现有恢复路径确认，不生成新 ID 盲目重做。
- 缓存同步或修复 ACK 失败不能把已提交 PG 数据解释成未提交；修复目标不得提前清除。
- 不缩短可靠 Redis AOF 确认、不丢 backlog、不更改 Outbox 租约/顺序/重试契约，不放宽验证探针错误分类。
- 维持游戏通用边界。默认不动 TiangZ 业务、协议、Core、WoW335；涉及共享 SDK 或接口时重新评估两者兼容性。

### 4. 精确测试先行

1. 持有连接锁，调用真实 Store 入口：等待超时返回，确认该等待者没有发送 SQL，取消后无残留等待与指标泄漏。
2. 多个并发调用遭遇同一次连接故障：计数实际连接尝试，验证恢复不会被重复重连覆盖、故障风暴被约束。
3. PG 已提交但 ACK 丢失：相同 ID 重试/查询返回既有结果，revision 只增长一次，事实和 Outbox 不重复。
4. 队列等待与执行预算隔离：正常长事务不得被“连接排队预算”误杀；取消/断连后后续事务的连接状态正确。
5. 批量保存、CommitRecords、旧 Trade、读取、修复 ACK 和维护 Worker 分别验证影响面；真实 PG 测试不能由模拟协议端点代替。
6. 参数默认/非法值、错误映射、恢复后健康请求以及阶段计时边界回归。

先做失败可复现的最小用例，再改代码，不以 sleep 后“还没结束”单独证明锁顺序。优先复用 `latency_path_tests.rs` 和现有真实故障测试。

### 5. 验证与验收

- 串行执行 DBProxy workspace 默认测试、全目标严格 Clippy、fmt/diff；真实数据库用例显式 `--ignored --test-threads=1`，默认 ignored 不算通过。
- 双仓库串行重建实际使用的 release；重新构建正常 Model/Hotfix 与探针，避免使用基准测试产物。修改 TiangZ 运行时/SDK 接线时按 AGENTS 执行对应门禁。
- 先短时冒烟，再做独立 30–60 分钟、100 游戏玩家 + 100 持久化探针的验证；先复用 r13 五故障方案便于比较。若改动影响进程恢复，再另跑相关 MapHost/Location/动态副本矩阵。
- 必须最终 SQL / Stream / 资产逐项对账，零旧读/缺失/不变量错误；每次故障后原账号两轮业务恢复。暂时错误和重试如实报告。
- 比较相邻采样增量、故障窗口和健康窗口，不相加/相减阶段 p99，不把桶边界写成精确分位数。换机结果需单独记资源基线，不与旧笔记本直接宣称百分比收益。
- 通过后更新两仓库结果文档并提交；失败时保留该轮证据，精确定位后新建运行目录，不能覆盖失败轮次。
