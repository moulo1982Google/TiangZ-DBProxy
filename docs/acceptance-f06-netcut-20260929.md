# F06 真实断网：失败定位与复测（2026-09-29）

本轮只操作 220 上的隔离测试容器。历史失败不改成通过；新结果使用新 RunId。

## 第三组失败原因

`f06_cut_off_c` 和 `f06_cut_on_c` 均退出 1。PG 从 `10.231.77.10` 断网 90 秒后在 `10.231.77.20` 恢复，旧地址没有占位容器。

- 关闭保护：业务连接仍被旧地址拖住，核对读取返回 StorageUnavailable，未生成完整 summary，不能判断全部写入一致。
- 默认保护：业务核对完成，17,782 次写入零差异。2026-09-29 对原始账本补跑原判定器，故障前和恢复后均零错误、零漏发，最后受影响请求距释放 0.120 秒；阶段规则通过。但整轮仍失败，因为宿主未正常退出。
- 两轮的采样连接都使用独立的原始 tokio-postgres 连接，直接等待 `pg_stat_activity`。服务端 `statement_timeout=500ms` 无法取消客户端在已经消失的网络路径上等待响应；采样循环因此不再检查停止文件。`host.exit=143` 是脚本最终终止宿主，不能说是正常停止。

正确修法：测试采样的连接、初始化和查询共用一秒客户端预算；失败/超时即丢弃客户端并中止其连接驱动，下次采样重新解析地址。记录采样缺口，不能伪造零负载，不能通过放宽停止预算掩盖问题。业务连接不使用这个采样预算。

新增本地静默 TCP 对端测试，验证采样不会无限等待。完整复测还必须证明断网期间持续产生采样、恢复后重新取得 PG 活动，以及宿主退出码为 0。

## 连接配置修正

默认发送超时 30 秒、空闲探测 30 秒、探测间隔 10 秒、探测次数 3；具体生效范围依赖操作系统。发送超时限制未获 TCP 确认的数据，**不是 SQL 执行的 30 秒上限**。中间代理仍确认 TCP 时，长 SQL 不能靠此保护取消；结果未知仍须保留原请求号重试。

旧实现通过 getter 的默认值猜测参数是否缺省，会覆盖显式 `tcp_user_timeout=0`、`keepalives_idle=7200` 等配置。改成驱动先验证连接串，再识别实际参数名，仅补缺省项。覆盖 URL、百分号编码参数名、关键字连接串，以及密码中含参数字样的情况。保留 tokio-postgres 0.7.18 自身对显式零值的解释。

该驱动的超时/间隔连接参数单位为秒，`keepalives_retries` 为次数；不要照搬 libpq 参数单位。检查锁定版本 `tokio-postgres 0.7.18/src/connect_socket.rs`：`tcp_user_timeout` 仅在 Linux TCP 连接上设置；Windows 不能引用本轮的 Linux 发送超时结论，Unix socket 也不走 TCP 保护。
