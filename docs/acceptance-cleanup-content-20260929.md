# A05/A15：清理前后完整内容与事务并发

RunId `ledger_20260929b`，新库同名，Linux 实际执行一项测试通过，耗时 3.69 秒。早一轮 `ledger_20260929a` 也通过，随后增加最终全量复核及近期回执逐列比较，完整结论以 b 轮为准。

## 内容账本

通过存储 API 生成单记录事务、多记录事务、通用 CommitRecords（两记录 + 不可变事实 + Outbox）、交易状态/双记录/零和账本/Outbox。每批四种事务均执行原请求重放并检查返回结果一致，其中一次 Outbox 经过真实领取和确认，保留已发布行。

从当前空库目录动态枚举 17 张非普通回执保护表。分区父表查询已覆盖所有分区数据，因此不再重复列每张分区。将每行全部列转为 PostgreSQL JSONB 文本，按行文本排序，保存清理前/后全量内容；比较的不只是行数、几条样本或散列。包含事务回执、multi records、追加事实、账本、已发布和未发布消息、缓存修复等表。

初始数据生成后清掉 1,000 条普通回执，17 张保护表逐列完全相同。随后十轮业务与非空清理批次使用独立连接并发执行，每轮清 500 条。最后再插入并清理 1,001 条过期夹具，对并发产生的全部保护内容再次逐列比较；100 条近期普通回执也与最初完整内容逐行比较。

## 结果

- 共 11 批业务，每批含四种事务，所有原请求重放结果一致。
- 77 条业务快照逐条核对键、载荷和 revision=1。
- 11 条追加事实、22 条账本及 22 条 Outbox 逐条核对预期内容。
- 每批另发一次冲突事实提交，共 11 次拒绝；每次拒绝前后全部保护表内容相同，没有半写入。
- 总共删除 7,001 条过期普通回执，100 条近期回执完整内容不变。
- 清理前后两次全量保护表比较均零差异，最终内容账本落盘。

这是实际存储 API 与真实 PG 的内容/事务验收，不是 TCP 端到端吞吐测量，也不是所有事务错误类型的笛卡尔积。并发阶段按十个批次交错执行，不声称两小时持续负载；原有单项原子性测试仍保留。没有后台 MQ/缓存消费任务擅自更改账本，Outbox 发布确认在取基线前完成。
