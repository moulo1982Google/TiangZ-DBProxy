# 通用持久化与领域边界调整计划

日期：2026-09-05。当前阶段只修改本地代码、测试和文档；远程七天演练继续使用原部署。结束后保存最终一致性报告、版本、配置与日志，再决定部署与补充验收。本文不授权清库、重启远程进程或提交 Git。

## 通用能力缺口与准入证据

普通多记录事务已有 CAS 和幂等回执，但不能同时提交追加事实和 Outbox。现有 Outbox 强制关联交易表，非交易领域无法使用。中立用例：更新两条版本化文档，同时追加一条审计事实和一个变更事件；任一条件失败全部回滚。请求仅包含记录键、版本、schema、字节、事件路由和操作 ID，不解析游戏 payload。

WoW335 的 Rust 领域仓库固定引用旧 DBProxy Git revision，使用 SnapshotWrite/load/save；外置模块使用 TiangZ 的 VersionedEntityRepository。不得改变这些接口、旧字段语义或快照 schema，不得把模块领域代码搬入 TiangZ 或 DBProxy。新增协议必须有准确的旧指纹兼容和握手测试，新客户端连接旧服务器须明确拒绝而非静默忽略新语义。

## 实施顺序

1. **DBProxy 通用提交**：增加组合式 CommitRecords 请求（多记录 CAS、只追加事实、Outbox、持久回执）；复用现有多记录事务与 Outbox worker；所有效果同一 PostgreSQL 事务。普通多记录请求保持原形状。重复请求须验证完整效果，不能以相同 ID 去掉事件重放。只追加记录以 namespace/key 唯一并禁止修改。
2. **领域适配**：TiangZ 通过已有 Repository/SDK 提交通用效果，MMORPG 交易规则与账本生成留在 model/hotfix 的领域目录。先接入真实玩家交易，避免只写无消费者的通用框架。新增能力不能要求 WoW335 迁移快照。
3. **兼容旧交易接口**：七天演练仍依赖旧 Trade API，暂时保留状态机、旧表与回执；标记为兼容入口，禁止新增消费者。待通用路径、恢复语义与调用迁移验收后单独退役，不能直接删除旧状态检查。
4. **验证与文档**：覆盖原子回滚、重复/篡改请求、跨 API 操作号冲突、事件/追加 ID 冲突、旧客户端握手、玩家交易与 WoW335 模块/快照契约。真实存储测试须在独立测试环境执行；不能使用当前远程演练的数据或服务。同步架构文档与 TiangZ 两份 AI 开发文档。

## 后续独立事项

2026-09-06 增量：继续在 DBProxy 本地实施通用 Relay/Redis Publisher、事件信封、持久路由、租约令牌、管理审计和分来源指标；Kafka/RabbitMQ 只预留禁用配置。详见 [Outbox Relay](outbox-relay.md)。TiangZ/WoW335 领域代码和远程部署不随本轮修改，持久托管及其他暂缓项仍等七天结果后处理。

本地第一批已打通通用提交和 TiangZ 在线交易审计/事件，不代表整份计划或持久托管迁移已经完成。旧 Trade API 继续承担已有客户端/演练的兼容语义。

生产保护（非 root、连接上限、超时/结果未知、背压、日志与发布门禁）单独实施，不与事务改造混为一次故障归因。只检查 revision 的读集合、删除 tombstone 按实际需求另行设计。暂不建设通用调度、分布式锁、经济引擎、邮件、赛季、分库或归档。

| C：领域恢复闭环 | TiangZ 领域模块保存交易单、托管状态、恢复决策；DBProxy 不解释状态转换 | 待实施；覆盖提交结果未知、进程退出、重复恢复与取消竞争，未确定结果不得报告取消 |
| D：退役专用入口 | DBProxy 旧 Trade API/表/SDK 与消费者逐项迁移 | 待 C 验收且七天旧版证据固定后再做；不得先删状态保护 |
| E：生产与发布验收 | 部署权限、连接与资源预算、超时/背压、日志留存和依赖固定 | 独立批次；新版真实存储演练、WoW 兼容和无本地补丁发布门禁通过后才部署 |
